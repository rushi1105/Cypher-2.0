# Cypher 2.0 — Deep Packet Analyser & Threat Detection System

Cypher is a PCAP-based deep packet analysis and ML-assisted anomaly scoring platform. A C++17 engine parses Ethernet/IPv4/TCP/UDP traffic, tracks bidirectional flows, extracts TLS SNI, HTTP Host, and DNS metadata, classifies applications, applies IP/app/domain block rules, and emits NDJSON plus a filtered PCAP. A FastAPI bridge replays the capture, aggregates windows into ML features, and exposes raw, enriched, window, stats, and threat streams.

> **Current status:** offline PCAP replay is working and has been verified end-to-end (engine -> FastAPI -> ML/rules -> SSE). A reproducible CIC-IDS2017 pipeline is complete, the 24-feature flow models are served at `/stream/flows`, and deterministic rules with MITRE ATT&CK mapping are served at `/stream/detections`. The legacy `/stream/windows` endpoints still use the old 11-feature model. Live capture, the dashboard, RAG explanations, Postgres, Docker, CI, and public deployment are in progress. See [ROADMAP.md](ROADMAP.md) for the exact state.

## What works today

- C++17 engine with classic `.pcap` reading and filtered `.pcap` output.
- Ethernet/IPv4/TCP/UDP parsing and bidirectional 5-tuple flow tracking.
- TLS SNI and HTTP Host extraction.
- DNS QNAME extraction.
- Application labels for roughly 48 named services plus generic HTTP/HTTPS/DNS/TLS/QUIC labels.
- IP, application, and domain block rules, including `*.example.com` wildcard domains.
- NDJSON per packet with:
  `ts`, `src`, `dst`, `sport`, `dport`, `proto`, `app`, `sni`, `blocked`, `size`, `flags`, `payload_len`, `direction`, `flow_id`, `block_reason`.
- Python PCAP shim used automatically when the C++ binary is unavailable.
- FastAPI endpoints for health, raw packets, ML-enriched packets, ML windows, flow predictions, stats, and threats.
- Legacy 11-window models on `/stream/enriched` and `/stream/windows`.
- CIC-IDS2017 24-feature flow model on `/stream/flows` (binary Random Forest, multi-class category, IsolationForest anomaly score).
- Deterministic rule engine on `/stream/detections`: port scan, SYN flood, DNS flood, brute force, suspicious port, beaconing, dominant talker, data exfiltration, and blocked-domain hit.
- MITRE ATT&CK mapping for every rule alert, exposed through `/rules` and the detection events.
- Synthetic attack demo in `engine/test_attack.pcap` generated by `engine/generate_attack_pcap.py`.
- Verified offline run: 77 packets, 27 flows, and six rule alerts on the attack PCAP. See [docs/DEMO_OUTPUT.md](docs/DEMO_OUTPUT.md).

## Architecture

```text
PCAP file
   |
   v
C++ DPI engine (NDJSON on stdout + filtered PCAP)
   |
   v
FastAPI bridge
   |-- PacketWindowBuffer (25 packets)
   |-- 11 features
   |-- Random Forest classifier
   |-- Isolation Forest anomaly detector
   |
   v
SSE endpoints: /stream, /stream/enriched, /stream/windows
REST endpoints: /health, /stats, /threats
```

## Requirements

- Python 3.11+
- Windows with PowerShell, or Linux/macOS with an equivalent shell
- C++ build toolchain: MSYS2 MinGW-w64 `g++`
- Optional, for future live capture: Npcap on Windows or libpcap on Linux
- Node.js 20+ only when working on the dashboard

## Quick start

### 1. Build the C++ engine

Install MSYS2 and the compiler:

```powershell
winget install MSYS2.MSYS2
```

In an MSYS2 shell:

```bash
pacman -S --needed mingw-w64-x86_64-gcc
```

Build from PowerShell:

```powershell
.\scripts\build-engine.ps1
```

This produces `engine\dpi_simple.exe`. The binary is intentionally not committed. If it is missing, the server falls back to `engine\engine_shim.py`.

### 2. Install Python dependencies

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r server\requirements.txt
```

### 3. Run the API

```powershell
.\scripts\run-server.ps1
```

Or manually:

```powershell
.\.venv\Scripts\python.exe -m uvicorn server.server:app --host 127.0.0.1 --port 8000
```

### 4. Check the endpoints

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
Invoke-RestMethod http://127.0.0.1:8000/stats
Invoke-RestMethod http://127.0.0.1:8000/threats
```

SSE streams are best consumed with a browser, `curl`, or the future dashboard:

```powershell
curl.exe -N http://127.0.0.1:8000/stream/windows
```

Run the engine tests:

```powershell
.\.venv\Scripts\python.exe -m pytest
```

Run the offline end-to-end check:

```powershell
.\.venv\Scripts\python.exe scripts\verify-offline-e2e.py
```

Expected result: `E2E_OK`, 77 enriched packets, and a final Pending partial window. The current model marks the synthetic capture as anomalous; treat its labels as a pipeline check, not a production detection result.

## Engine CLI

```text
dpi_simple.exe <input.pcap> <output.pcap> [options]

Options:
  --block-ip <ip>        Block traffic to or from this IP
  --block-app <app>      Block application (YouTube, TikTok, etc.)
  --block-domain <dom>   Block domain (substring or *.example.com)
  --json                 Emit one JSON object per packet to stdout
```

Example:

```powershell
.\engine\dpi_simple.exe .\engine\test_dpi.pcap .\engine\output.pcap --json --block-app YouTube
```

In JSON mode, human-readable logs go to stderr so stdout stays clean for the FastAPI reader.

## API endpoints

| Endpoint | Purpose |
|---|---|
| `GET /health` | Liveness, engine status, ML status, uptime |
| `GET /stream` | Raw NDJSON packet stream as SSE |
| `GET /stream/enriched` | Packet stream with the latest legacy window prediction |
| `GET /stream/windows` | One event per completed 25-packet window (legacy 11-feature model) |
| `GET /stream/flows` | One event per completed/expired flow (24-feature CIC-IDS2017 model) |
| `GET /stream/detections` | Flow events plus deterministic rule alerts and MITRE mapping |
| `GET /rules` | Rule catalog and MITRE ATT&CK technique metadata |
| `GET /stats` | Accumulated packet, window, flow, detection, attack, anomaly, and app stats |
| `GET /threats` | Recent window, flow, and rule threat/anomaly events |

All stream endpoints accept an optional `?pcap=filename.pcap` restricted to the `engine/` directory. Example:

```powershell
curl.exe -N "http://127.0.0.1:8000/stream/detections?pcap=test_attack.pcap"
```

## ML training status

The reproducible pipeline lives in `ml/` and downloads CIC-IDS2017 into ignored storage.

Binary Random Forest, held-out test split:

| Operating point | Precision | Recall | F1 | FPR |
|---|---:|---:|---:|---:|
| Deployment 0.50 | 0.9903 | 0.8963 | 0.9410 | 0.0019 |
| High-recall 0.02 | 0.8168 | 0.9516 | 0.8791 | 0.0455 |

- Test ROC-AUC: 0.9922
- Test PR-AUC: 0.9797
- IsolationForest test ROC-AUC: 0.8416

See [ml/reports/model_card.md](ml/reports/model_card.md) for the full report, limitations, and the multi-class results. The new models use 24 flow features and are served at `GET /stream/flows`. The legacy `/stream/windows` path still uses the old 11-feature model until it is retired.

## Rule engine and MITRE mapping

The deterministic layer runs alongside the flow ML model:

| Rule | Severity | MITRE |
|---|---|---|
| Port scan | High | T1046 Network Service Discovery |
| SYN flood | High | T1498 Network Denial of Service |
| DNS flood | Medium | T1498 Network Denial of Service |
| Brute force | High | T1110 Brute Force |
| Suspicious port | High | T1571 Non-Standard Port |
| Beaconing | Medium | T1071 Application Layer Protocol |
| Dominant talker | Low | T1498 Network Denial of Service |
| Data exfiltration | High | T1048 Exfiltration Over Alternative Protocol |
| Blocked domain hit | Medium | T1071.001 Web Protocols |

Generate and run the attack demo:

```powershell
.\.venv\Scripts\python.exe .\engine\generate_attack_pcap.py
.\scripts\run-server.ps1
curl.exe -N "http://127.0.0.1:8000/stream/detections?pcap=test_attack.pcap"
```

Expected attack rules:

```text
port_scan, syn_flood, dns_flood, suspicious_port, brute_force, beaconing
```

The rule engine supports suppression windows, per-rule evidence, severity counters, and ATT&CK metadata. The ML flow model alone did not flag the synthetic one-packet attack flows; the hybrid rule layer is what catches them.

## Current limitations

- The server replays a fixed `engine/test_dpi.pcap`; it does not capture live traffic yet.
- The dashboard is not built yet.
- The legacy `/stream/windows` model uses 11 features; `/stream/flows` uses the new 24-feature model.
- The CIC-IDS2017 pipeline has no self-captured baseline or controlled lab attack traffic yet.
- Serving features approximate CICFlowMeter semantics using the engine JSON; packet bytes are estimated as frame size minus the Ethernet header.
- Single-packet flows from the synthetic blocked-IP traffic were not flagged by the flow model; rule-based detection is still required.
- Rule thresholds are heuristic and have not been tuned on real traffic. Expect false positives and overlap between rules.
- No TCP stream reassembly, IPv6, VLAN, PCAPNG, QUIC, or TLS 1.3 ECH handling.
- Blocking is offline and only affects the generated output PCAP.
- No Postgres, Docker, CI, auth, or public deployment yet.

## Privacy and scope

Use Cypher only on traffic you own or have explicit permission to analyse. Do not commit real user PCAPs, credentials, or personal data. The project does not decrypt TLS; it reads plaintext handshake metadata such as SNI and HTTP Host. Live capture and public deployment are planned as local/self-hosted features, not public interception.
